# Houdoku 汉化原理

本文说明 `houdoku-zh-cn` 是如何在不修改 Houdoku 源码、不重新编译的前提下，让官方安装包显示简体中文的。

- 目标版本：Houdoku 2.16.0（Electron 应用，Windows x64）
- 目标文件：`<安装目录>\resources\app.asar`

---

## 1. 背景：为什么不能"改设置"

对 `app.asar` 解包后检索可确认：

- `package.json` 中没有任何 i18n 依赖（无 `i18next`、`react-intl`、`@formatjs` 等）；
- 渲染进程 bundle 中不存在语言包文件，也没有 `language` / `locale` 设置项；
- 界面文案（按钮、标题、提示、对话框）全部以英文字符串字面量硬编码在 JSX 中；
- 唯一与"语言"相关的枚举是**漫画内容语言**（`CHINESE_SIMP` 等），属于内容元数据，与界面语言无关。

因此不存在"切换到中文"的设置项，只能在安装包层面做本地化。

---

## 2. 目标与约束

| 约束 | 说明 |
| --- | --- |
| 不改业务逻辑 | 不改变任何功能、网络请求、存储结构 |
| 不改用户数据 | 不影响书库、进度、插件、设置 |
| 不能破坏枚举 | `SeriesStatus`、`TrackerStatus` 等枚举值参与逻辑与持久化，必须保持英文原值 |
| 可回滚 | 保留原始 `app.asar` 备份 |
| 可重复构建 | 构建脚本可重复执行，结果一致 |

关键点在于第三行：**界面上显示的中文，不能写回数据层**。例如状态筛选器的选项显示"在读"，但其 `value` 必须仍然是 `"READING"`。

---

## 3. 方案选型

| 方案 | 做法 | 问题 |
| --- | --- | --- |
| A. 源码级 i18n | 拉取上游源码，引入 i18n 框架，改所有 JSX，再重新编译 | 工作量大；需要完整构建环境；与上游版本强耦合；重新编译的产物与官方包差异大 |
| B. 静态字符串替换 | 直接把 bundle 里的英文替换成中文 | 会同时改到枚举值、存储键、比较逻辑，极易导致功能异常；动态拼接文案无法覆盖 |
| C. 运行时注入翻译层 | 在 bundle 中注入一层翻译函数，拦截 React 元素创建，只翻译"将要显示"的文本 | 需要理解打包结构与 JSX runtime；但风险最低、可回滚、可重复构建 |

本项目采用 **方案 C**。

## 4. 安装包结构：asar 格式

### 4.1 磁盘布局

```
app.asar
├─ [8 字节前缀]
│   ├─ uint32 = 4          // pickle 头长度
│   └─ uint32 = headerSize // header 总长度
├─ [header: headerSize 字节]
│   ├─ uint32 = 4 + paddedJsonLen
│   ├─ uint32 = jsonLen
│   ├─ JSON（文件树，含每个文件的 size / offset / integrity / unpacked）
│   └─ 4 字节对齐填充
└─ [数据区：所有文件内容按 offset 顺序排列]
```

### 4.2 最重要的一条规则

**JSON 中的 `offset` 是相对"数据区起点"的偏移，不是相对文件开头的绝对偏移。**

因此读取某个文件时：

```js
const dataStart    = 8 + headerSize;
const absolutePos  = dataStart + parseInt(entry.offset, 10);
const content      = readSync(fd, entry.size, absolutePos);
```

这一点在重打包时尤其关键：header 大小变化后，**所有旧条目的 `offset` 都不需要改动**，因为数据区整体平移，条目之间的相对位置不变。

### 4.3 unpacked 条目

原生模块（`.node`）、可执行文件等在打包时被放在 `resources/app.asar.unpacked/` 下，JSON 中对应条目的 `unpacked: true`，**没有 `offset` 字段**。遍历时必须跳过，否则会得到 `NaN` 偏移并抛 `ERR_OUT_OF_RANGE`。

### 4.4 integrity 字段

官方包中每个文件带有 `integrity`（SHA256）。修改文件内容后必须**删除该条目的 `integrity` 字段**，否则 Electron 启动时会因校验失败而拒绝加载。

另外，官方包中存在个别 `offset: "0"` 的历史坏条目（如 `node_modules/@ampproject/remapping/LICENSE`），重打包与校验时按原样保留并跳过。

## 5. 注入点：渲染进程 bundle

### 5.1 产物形态

`app.asar` 中的 `out/renderer/assets/index-*.js` 是 Vite 打出的**未压缩 ESM bundle**（约 1.7 MB），因此可读、可按行定位。文件包含 top-level await，语法校验需要使用 `.mjs`：

```powershell
# 以 Electron 自带的 Node 运行
$env:ELECTRON_RUN_AS_NODE=1
Houdoku.exe --check check.mjs
```

### 5.2 为什么可以拦截

React 17+ 的自动 JSX runtime 在 bundle 中被这样引入：

```js
var jsxRuntimeExports = jsxRuntime.exports;   // 普通可变对象
var reactExports      = react.exports;
```

所有 JSX 最终都会调用 `jsxRuntimeExports.jsx` / `jsxs`，而手写 `React.createElement` 调用则走 `reactExports.createElement`。二者都是**普通对象上的属性**，可以在运行时替换：

```js
jsxRuntimeExports.jsx  = wrapJsx(jsxRuntimeExports.jsx);
jsxRuntimeExports.jsxs = wrapJsx(jsxRuntimeExports.jsxs);
reactExports.createElement = function (type, config, ...children) { /* ... */ };
```

拦截发生在"元素创建"这一层，此时文本还是原始字符串，**尚未写入 DOM，也尚未进入任何业务逻辑**。

## 6. 翻译层设计

注入代码位于 `patch/zh-runtime.js`，整体是一个 IIFE：

```js
(() => {
  const DICT = { /* 精确词典 */ };
  const RAW  = { /* 需要保留前后空格的片段 */ };
  const DYN  = [ /* 动态规则（正则） */ ];

  function trCore(core) { ... }   // 核心翻译
  function tr(s) { ... }          // 保留空白的外层包装
  function trNode(v) { ... }      // 递归 children
  function trProps(props) { ... } // 只处理显示属性
  function wrapJsx(fn) { ... }    // 包装 jsx/jsxs
})();
```

### 6.1 只翻译"显示属性"

```js
const DISPLAY_PROPS = ["children", "placeholder", "title", "alt", "aria-label"];
```

只处理这五个属性，原因：

- `children` 是界面文本；
- `placeholder` / `title` / `alt` / `aria-label` 是可见或可访问性文本；
- 其余属性（`value`、`id`、`data-*`、`className`、`onClick`……）**一律不动**，从而保证枚举值、存储键、路由、样式类名完全不变。

### 6.2 children 的三种形态

`children` 可能是字符串、数组或 React 元素：

```js
function trNode(v) {
  if (typeof v === "string") return tr(v);
  if (Array.isArray(v)) {
    let changed = false;
    const out = v.map((item) => {
      const nv = trNode(item);
      if (nv !== item) changed = true;
      return nv;
    });
    return changed ? out : v;   // 未变化时返回原数组，避免无谓的重渲染
  }
  return v;                     // React 元素 / 数字 / null 原样返回
}
```

JSX 中的文本片段常常被拆成多个子节点，例如：

```jsx
<span>{count} chapter(s) selected.</span>
```

实际 children 是 `[count, " chapter(s) selected."]`，所以数组必须逐个递归处理。

### 6.3 空白字符的处理

英文文案里的空格带有语义：

```jsx
["Authenticate on ", <Link/>, " account on the ", <Link/>, " page."]
```

如果直接 `trim()` 后查词典再返回，会丢掉空格，导致中文与链接文字粘连。因此分两层：

```js
function tr(s) {
  if (typeof s !== "string" || !s || s.length > 300) return s;
  if (!/[A-Za-z]/.test(s)) return s;

  // 1) 带空格片段：精确匹配
  if (Object.prototype.hasOwnProperty.call(RAW, s)) return RAW[s];

  // 2) 拆出前后空白，只翻译核心部分，再把空白拼回
  const m = /^(\s*)([\s\S]*?)(\s*)$/.exec(s);
  const core = m[2];
  if (!core) return s;
  const out = trCore(core);
  return out === core ? s : m[1] + out + m[3];
}
```

- `RAW`：需要保留空格的固定片段，如 `"Chapter "` → `"第 "`、`" of "` → `" / "`；
- `DICT`：不带空格的精确词典；
- 最终返回值始终保留原始前后空白。

### 6.4 动态文案

单靠词典无法覆盖带数字或标题的文案，因此有两类动态处理。

**正则规则 `DYN`：**

```js
const DYN = [
  [/^Vol\. (.+) · $/, "第 $1 卷 · "],
  [/^Reloading series (\d+)\/(\d+)$/, "正在刷新漫画 $1/$2"],
  [/^Failed to update (\d+) series$/, "$1 部漫画更新失败"],
  [/^Error while reloading series "(.+)"$/, "刷新漫画「$1」时出错"],
  [/^ by (.+)$/, "由 $1 汉化"],
  [/^Page (.+) of (.+)$/, "第 $1 页 / 共 $2 页"],
  [/^Chapter (.+) of (.+)$/, "第 $1 话 / 共 $2 话"]
];
```

**通用片段替换：**

```js
core
  .replace(/\bChapter (\d+(?:\.\d+)?)/g, "第 $1 话")
  .replace(/\bCh\. (\d+(?:\.\d+)?)/g, "第 $1 话")
  .replace(/\bPage (\d+)/g, "第 $1 页")
  .replace(/\bVol\. (\d+(?:\.\d+)?)/g, "第 $1 卷")
  .replace(/Unknown Chapter/g, "未知章节");
```

### 6.5 词典的组织

`DICT` 按界面区域分组，便于维护：

```js
const DICT = {
  // 导航 / 页面
  "Add Series": "添加漫画",
  "Library": "书库",
  // 设置
  "Theme": "主题",
  "Light": "浅色",
  // 阅读器
  "Page Style": "页面样式",
  "Single Page": "单页",
  // 下载
  "Download Queue": "下载队列",
  // 对话框 / 错误页
  "Are you sure you want to remove": "确定要从书库移除",
  // 漫画内容语言
  "English": "英语",
  ...
};
```

命名冲突时以"整条文本"为 key，不做单词级替换（如 `"Light"` → `"浅色"` 只对独立文本节点生效，不会误伤类名 `light`）。

## 7. 静态替换

运行时翻译覆盖不到两类文本：

| 类型 | 位置 | 处理 |
| --- | --- | --- |
| 系统对话框标题 | 渲染进程中传给 IPC 的字面量 | 直接替换字符串，如 `"Select backup file"` → `"选择备份文件"` |
| 主进程通知 | `out/main/index.js` 中的 `SEND_NOTIFICATION` 参数 | 直接替换，如 `"Houdoku is up-to-date!"` → `"Houdoku 已是最新版本！"` |

替换清单（`patch/patch-bundle.js`）：

```js
const repl = [
  ['"Select backup file"', '"选择备份文件"'],
  ['"Select Downloads Directory"', '"选择下载目录"'],
  ['"Select Series Directory"', '"选择漫画目录"'],
  ['"Select Series Cover"', '"选择漫画封面"'],
  ['"Houdoku Backup"', '"Houdoku 备份"'],
  ['"Select series file"', '"选择漫画文件"'],
  ['name: "Image",', 'name: "图片",'],
];
```

主进程另有一组通知文案替换（检查更新、下载更新、更新失败等）。

> 静态替换只针对**纯展示文案**，且都在替换前确认全包内出现次数，避免误伤代码。

## 8. 重新打包 app.asar

`patch/repack.js` 的流程：

1. **以官方原始 `app.asar` 为基准**（不是以已汉化的包为基准），保证可重复构建；
2. 读取 header，得到 `headerSize`、`dataStart`、`oldDataSize`；
3. 对每个被修改的文件条目：
   - 更新 `size`；
   - **删除 `integrity`**；
   - `offset` 稍后统一改为新数据的位置；
4. 重建 header（JSON 长度变化会让 header 大小变化，迭代直到稳定）；
5. 把原数据区**原样复制**到新 header 之后（旧条目的 `offset` 无需改动）；
6. 把修改过的文件追加到数据区末尾，`offset = oldDataSize`、`oldDataSize + size1`、……

关键代码：

```js
// 追加位置从原数据区末尾开始
let appendOffset = oldDataSize;
for (const [key, buf] of changed) {
  findEntry(json, key).offset = String(appendOffset);
  appendOffset += buf.length;
}
```

header 重建：

```js
const jsonStr   = JSON.stringify(json);
const jsonLen   = Buffer.byteLength(jsonStr);
const paddedJson = (jsonLen + 3) & ~3;
const headerSize = 8 + paddedJson;

header.writeUInt32LE(4, 0);
header.writeUInt32LE(headerSize, 4);
header.writeUInt32LE(4 + paddedJson, 8);
header.writeUInt32LE(jsonLen, 12);
header.write(jsonStr, 16, 'utf8');
```

## 9. 校验

`patch/verify.js` 对重新打包后的 asar 做**全量校验**：

1. 按新 header 解析文件树；
2. 对每个非 unpacked、`size > 0`、`offset > 0` 的条目：
   - 以 `dataStart + offset` 读取 `size` 字节；
   - 与解包目录中的同名文件计算 SHA256 并比较；
3. 输出 `checked / bad / unpacked`。

本项目实测结果：

```text
checked 18684 bad 0 unpacked 68
```

即 18684 个文件全部一致，仅 68 个 unpacked 原生模块不参与比较（它们本来就放在 asar 外，未被修改）。

另有启动级验证：以 `--remote-debugging-port` 启动应用，通过 CDP 读取 `document.body.innerText`，确认界面为中文且无渲染报错。

## 10. 复现步骤

以 Windows + 官方 2.16.0 安装包为例：

```powershell
# 0. 准备目录
mkdir work
cd work

# 1. 解包 app.asar（注意跳过 unpacked 条目）
#    可用 npx asar extract 或自行按第 4 节结构解析

# 2. 注入翻译运行时与静态替换
$env:ELECTRON_RUN_AS_NODE=1
Houdoku.exe patch-bundle.js

# 3. 以官方原始包为基准重新打包
Houdoku.exe repack.js

# 4. 全量校验
Houdoku.exe verify.js

# 5. 覆盖安装（先退出应用）
Copy-Item app.asar.new "<安装目录>\resources\app.asar" -Force
```

`patch/` 下的脚本使用可配置路径，顶部常量即为输入 / 输出位置。

## 11. 适配新版本

上游发布新版本后：

1. 解包新版本 `app.asar`；
2. 确认渲染入口文件名是否变化（`out/renderer/assets/index-*.js`）；
3. 确认 `var jsxRuntimeExports = jsxRuntime.exports;` 这一行是否存在（注入锚点）；
4. 用新版本界面重新跑一遍文案提取，补充 `DICT` 中新增或变更的条目；
5. 重新执行第 10 节流程，并做 CDP 界面巡检。

由于翻译层依赖的是 React JSX runtime 这一稳定接口，上游普通功能更新通常只需补充词典，不需要重写逻辑。

---

## 12. 局限与风险

- **版本绑定**：补丁只适配构建时对应的版本，文件结构变化会导致注入失败（脚本会显式报错）；
- **升级覆盖**：Houdoku 自动更新会覆盖 `app.asar`，需重新安装补丁；
- **动态拼接**：极少数运行时拼接的文案可能未被规则覆盖，仍显示英文；
- **外部内容**：插件（Tiyo 扩展）抓取到的漫画元数据不属于界面文案，不翻译；
- **非官方**：本项目与 Houdoku 作者无关，请遵守 MIT 协议并支持原作者。
